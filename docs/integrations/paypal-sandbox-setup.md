# PayPal Sandbox Setup

> **TL;DR**
> - Use the default sandbox Business account as the fictional shop "Kahon Goods" (sender).
> - Create 6 sandbox vendor accounts plus 1 attacker account, all with fictional names. Record their sandbox emails only in your local `.env` or seed config, never in the public repo.
> - Create a REST app, copy client ID and secret to `.env`, enable Payouts and Transaction Search on Day 1.
> - Register webhook URL `https://{tunnel-or-render-host}/webhooks/paypal` and subscribe to all `PAYMENT.PAYOUTS*` events.
> - **Status: planned.** No seed config or env keys for PayPal exist in the repo yet.

## 1. Accounts

| # | Sandbox account | Type | Role in demo | Notes |
|---|---|---|---|---|
| 1 | Kahon Goods (default sandbox Business) | Business | Sender | Confirm a USD balance |
| 2 | BoxPro Supplies | Personal or Business | Vendor | Packaging boxes |
| 3 | PrintHub | Personal or Business | Vendor | Printing, price-jump scene |
| 4 | TapeWorks | Personal or Business | Vendor | Tape, line-item anomaly eval case 7 |
| 5 | Filler Co | Personal or Business | Vendor | Filler |
| 6 | LensLab Photo | Personal or Business | Vendor | Photographer |
| 7 | VA freelancer | Personal | Vendor | Freelance VA |
| 8 | Attacker | Personal | Impersonation payee | Proves the payout would have landed (PRD 11.1) |

Public repo rule (PRD 18, C10): only fictional brands. Never commit real personal emails. Sandbox emails generated by PayPal go into local config only. Seed data uses placeholder `@sandbox.example` style emails mapped from env (open question OQ-13 covers the PRD's real-looking `boxpro.ph` / `boxpro-ph.com` domains; default is to use `.example` domains in committed data).

## 2. REST app

| Step | Action | Result |
|---|---|---|
| 1 | Log in at developer.paypal.com, open Apps and Credentials (Sandbox) | App list |
| 2 | Create a REST app under the Kahon Goods Business account | Client ID and secret |
| 3 | Copy into local `.env`: `PAYPAL_MODE=sandbox`, `PAYPAL_CLIENT_ID=...`, `PAYPAL_CLIENT_SECRET=...` | Never commit values |
| 4 | In app features, enable **Payouts** and **Transaction Search** if shown | Transaction Search can take up to 9 h to apply to new tokens. Do this first on Day 1 |

## 3. Webhook

| Step | Action |
|---|---|
| 1 | Start a public tunnel to the local app (cloudflared or ngrok), or use the Render host |
| 2 | Add webhook URL `https://{host}/webhooks/paypal` |
| 3 | Subscribe: `PAYMENT.PAYOUTSBATCH.PROCESSING`, `PAYMENT.PAYOUTSBATCH.SUCCESS`, `PAYMENT.PAYOUTSBATCH.DENIED`, `PAYMENT.PAYOUTS-ITEM.SUCCEEDED`, `PAYMENT.PAYOUTS-ITEM.FAILED`, `PAYMENT.PAYOUTS-ITEM.DENIED`, `PAYMENT.PAYOUTS-ITEM.BLOCKED`, `PAYMENT.PAYOUTS-ITEM.HELD`, `PAYMENT.PAYOUTS-ITEM.UNCLAIMED`, `PAYMENT.PAYOUTS-ITEM.RETURNED`, `PAYMENT.PAYOUTS-ITEM.REFUNDED`, `PAYMENT.PAYOUTS-ITEM.CANCELED` |
| 4 | Copy the webhook ID into `.env` as `PAYPAL_WEBHOOK_ID` |
| 5 | Test with a real sandbox payout. The Webhooks Simulator sends mock events that fail signature verification |

Local tunnel URLs change on restart; update the webhook URL each time or use a named tunnel.

## 4. Verification checklist (Day-1 spike, PRD 16.5)

| Check | Pass |
|---|---|
| OAuth token | 200 with `access_token` |
| $5.00 payout to BoxPro sandbox with `sender_batch_id=SPIKE-1` | 201 |
| Same `sender_batch_id` again | Duplicate error with link |
| Webhook through tunnel | `PAYMENT.PAYOUTS-ITEM.SUCCEEDED` received |
| Verify signature | `SUCCESS` |
| Payout to an email with no sandbox account (optional, OQ-11) | `UNCLAIMED` |

See [paypal-payouts.md](./paypal-payouts.md) section 9 for go/no-go and fallback.
