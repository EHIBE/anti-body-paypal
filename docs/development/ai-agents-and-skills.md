# AI Agents and Skills Guide

> **TL;DR**
> - 10 project agents live in `.claude/agents/<name>.md`, each with `model: claude-sonnet-5-5`, `effort: medium` and least-privilege tools. 4 are read-only reviewers or planners.
> - 12 project skills live in `.claude/skills/<name>/SKILL.md`, security first. 5 more skills are Boost-managed and regenerated by `php artisan boost:update`.
> - Work follows the feature prompt phases: LOAD, CLARIFY (gate), IMPLEMENT, VERIFY, DOCUMENT, REPORT.
> - Read-only explorers may run in parallel. Only one writer per file. Verify every agent result against source.

## 3. Boost-managed skills

These are generated by Laravel Boost (`boost.json` `skills`) into `.claude/skills/`, `.agents/skills/` and `.cursor/skills/`. `php artisan boost:update` (run on `post-update-cmd`) regenerates them, so local edits are overwritten.

| Skill | Use |
|---|---|
| laravel-best-practices | Any Laravel PHP code |
| testing-best-practices | Test design and review |
| tailwindcss-development | Blade or Tailwind styling |
| deploying-to-cloud | Laravel Cloud only (Anti-Body deploys to Render, normally skip) |
| infer-conventions | Only when the owner asks to record conventions in `.ai/rules` |

Other skills available in Claude Code (user or plugin level): `security-review`, `code-review`, `simplify`, `claude-api` (model IDs, laravel/ai prompts), `impeccable`, `frontend-design`, `high-end-visual-design`, `minimalist-ui` (Filament polish).

## 5. Feature prompt workflow

```mermaid
flowchart LR
  L[LOAD: read CLAUDE.md, AGENTS.md, .ai/rules, docs, code, skills] --> C{CLARIFY gate: numbered questions with defaults}
  C -->|answers or use defaults| I[IMPLEMENT: design first, slices, SOLID, security]
  I --> V[VERIFY: composer ci:check (Rector, Pint, Larastan max, audits, build, Pest), hook proofs]
  V --> D[DOCUMENT: docs, CLAUDE.md and AGENTS.md state, queue, bugs]
  D --> R[REPORT: per-block prose, files, skills, agents, commits]
```

| Phase | Output |
|---|---|
| LOAD | Read `.ai/rules/index.md` and matching rule files; one-sentence current project state |
| CLARIFY | Numbered questions with recommended defaults; stop until answered |
| IMPLEMENT | Full feature, no stubs or TODOs, small commits `type: [ABP-#] Action` |
| VERIFY | Zero new failures or violations |
| DOCUMENT | Docs updated in place |
| REPORT | Files changed, skills and agents used, verification results |

## 6. Rules for agents

| # | Rule |
|---|---|
| 1 | Read-only explorers may run in parallel; one writer per file |
| 2 | Verify every agent result against source before relying on it |
| 3 | Hard constraints in CLAUDE.md and AGENTS.md win over skill instructions |
| 4 | No dependency, slice or base-folder changes without approval |
| 5 | No git push, merge, rebase, stash, reset, checkout, branch creation or amend |
| 6 | No `Co-Authored-By` or AI attribution in commits |
| 7 | Zero code comments except PHPDoc types and array shapes |
| 8 | Sandbox PayPal only; local environment only |
| 9 | Before planning or editing, open `.ai/rules/index.md`, read every rule file whose globs match the paths in scope, and run `grep -rin '<keyword>' .ai/rules` (section 7) |

## 7. Project rules in `.ai/rules` (implemented)

`.ai/rules/` holds 15 path-scoped rule files recorded by ABP-8 through the Laravel Boost `record-rule` tool. `.ai/rules/index.md` maps file globs to rule files.

| Rule file | Applies to |
|---|---|
| `.ai/rules/app.md` | `app/**/*.php` |
| `.ai/rules/features.md` | `app/Features/**` |
| `.ai/rules/actions.md` | `app/Features/*/Actions/**` |
| `.ai/rules/data.md` | `app/Features/*/Data/**` |
| `.ai/rules/enums.md` | `app/Features/*/Enums/**` |
| `.ai/rules/models.md` | `app/Features/*/Models/**` |
| `.ai/rules/traits.md` | `app/Features/*/Models/Traits/**` |
| `.ai/rules/routes.md` | `app/Features/*/Routes/**` |
| `.ai/rules/tests.md` | `app/Features/*/Tests/**` |
| `.ai/rules/guard.md` | `app/Features/Guard/**` |
| `.ai/rules/payment.md` | `app/Features/Payment/**` |
| `.ai/rules/agent-gateway.md` | `app/Features/AgentGateway/**` |
| `.ai/rules/audit.md` | `app/Features/Audit/**` |
| `.ai/rules/filament.md` | `app/Filament/**` |
| `.ai/rules/migrations.md` | `database/migrations/**` |

| Rule about rules | Detail |
|---|---|
| How rules are added | Only through the Boost `record-rule` MCP tool, and only when the owner explicitly asks (the `infer-conventions` skill applies only on explicit request) |
| Hand edits | Do not hand-write or reformat `.ai/rules` files; Boost owns the format and the index |
| Precedence | `.ai/rules` and CLAUDE.md / AGENTS.md constraints win over skill instructions |
